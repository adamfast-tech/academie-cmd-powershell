=== ps ¦ PowerShell ¦ ps ¦ Des objets plutôt que du texte : cmdlets, pipeline, inventaire, journaux, registre et scripts .ps1.
--- Premiers pas
### LESSON p1 ¦ Verbe-Nom : la grammaire de PowerShell ¦ 1 ¦ Pourquoi toutes les commandes se ressemblent, et comment deviner celle qu’il te faut.
>>> info ¦ Une commande = un verbe + un nom
En PowerShell, les commandes s’appellent des **cmdlets** (prononce « commande-lettes » : de petites commandes). Elles suivent toutes le même modèle :
```anatomy ps
Get ¦ cmd ¦ Le **verbe** : l’action. Toujours au début, issu d’une liste officielle.
- ¦ op ¦ Un trait d’union, sans espace.
Service ¦ cmd ¦ Le **nom** : l’objet sur lequel on agit, toujours au **singulier**.
```
Donc : `Get-Service`, `Stop-Service`, `Start-Service`, `Restart-Service`… et `Get-Process`, `Stop-Process`, `Get-ADUser`, `Unlock-ADAccount`.
!tip Si tu connais un verbe et un nom, tu connais déjà la commande. Un utilisateur à déverrouiller ? Verbe `Unlock`, nom `ADAccount`.
>>> info ¦ Les verbes à connaître
```table
Verbe ¦ Sens ¦ Exemple
`Get` ¦ lire, obtenir ¦ `Get-Process`
`Set` ¦ modifier ¦ `Set-Service`
`New` ¦ créer ¦ `New-Item`, `New-ADUser`
`Remove` ¦ supprimer ¦ `Remove-Item`
`Start` / `Stop` / `Restart` ¦ démarrer / arrêter / redémarrer ¦ `Restart-Service`
`Add` / `Clear` ¦ ajouter / vider ¦ `Add-Content`, `Clear-RecycleBin`
`Test` ¦ vérifier (renvoie Vrai/Faux) ¦ `Test-Path`, `Test-Connection`
`Enable` / `Disable` ¦ activer / désactiver ¦ `Disable-ADAccount`
`Import` / `Export` ¦ charger / enregistrer ¦ `Import-Csv`, `Export-Csv`
`ConvertTo` / `ConvertFrom` ¦ changer de format ¦ `ConvertTo-Json`
```
`Get-Verb` les liste tous (une centaine).
>>> qcm ¦ Quelle cmdlet redémarre un service ?
+ `Restart-Service`
* `Reboot-Service`
* `Service-Restart`
* `Restart-Services`
? Verbe approuvé `Restart`, puis nom **au singulier**. `Reboot` n’est pas un verbe approuvé.
>>> type ps ¦ Affiche l’état du service Spooler.
= Get-Service Spooler ;; Get-Service -Name Spooler ;; gsv Spooler ;; Get-Service spooler
```out

Status   Name               DisplayName
------   ----               -----------
Running  Spooler            Spouleur d’impression
```
>>> info ¦ La casse et la complétion
- PowerShell **ignore la casse** : `get-service`, `GET-SERVICE` et `Get-Service` sont identiques. On écrit `Get-Service` par lisibilité.
- La touche **Tab** complète les noms de cmdlets, de paramètres et de chemins : tape `Get-Ser` puis Tab.
- Sur téléphone, le bouton **Tab** de la barre de symboles fait de même dans le terminal du site.
>>> info ¦ Les alias : des raccourcis
Un **alias** est un surnom. PowerShell en fournit pour les habitués de CMD et de Linux :
```table
Alias ¦ Cmdlet réelle
`dir`, `ls`, `gci` ¦ `Get-ChildItem`
`cd`, `sl` ¦ `Set-Location`
`cls` ¦ `Clear-Host`
`type`, `cat`, `gc` ¦ `Get-Content`
`copy`, `cp` ¦ `Copy-Item`
`del`, `rm` ¦ `Remove-Item`
`ps`, `gps` ¦ `Get-Process`
`gsv` ¦ `Get-Service`
`?`, `where` ¦ `Where-Object`
`%`, `foreach` ¦ `ForEach-Object`
```
!warn `dir` en PowerShell n’est **pas** le dir de CMD : `dir /s` échoue. C’est `Get-ChildItem -Recurse`. L’alias ne change que le nom, pas les paramètres.
>>> type ps ¦ Découvre quelle cmdlet se cache derrière l’alias `gci`.
= Get-Alias gci ;; Get-Alias -Name gci ;; gal gci
```out

CommandType     Name                                               Version    Source
-----------     ----                                               -------    ------
Alias           gci -> Get-ChildItem
```
? Bonne pratique : alias en console pour aller vite, noms complets dans les **scripts**, pour qu’ils restent lisibles par tes collègues.
>>> qcm ¦ Pourquoi `dir /s` échoue-t-il dans PowerShell ?
+ `dir` est un alias de Get-ChildItem, qui ne connaît pas `/s` : il faut `-Recurse`
* PowerShell ne sait pas lister les fichiers
* Il faut être administrateur
* `/s` doit s’écrire en majuscules
? En PowerShell, les paramètres commencent par `-`. `/s` est pris pour un chemin.

### LESSON p2 ¦ Paramètres : nommés, positionnels, commutateurs ¦ 1 ¦ -Name, -Path, -Recurse… et pourquoi tu peux parfois les omettre.
>>> info ¦ Anatomie d’une commande avec paramètres
```code ps
Get-ChildItem -Path C:\Logs -Filter *.log -Recurse
```
```anatomy ps
Get-ChildItem ¦ cmd ¦ La cmdlet : « obtenir les éléments enfants » (fichiers et dossiers).
-Path ¦ param ¦ Un **paramètre** : un nom précédé d’un tiret…
C:\Logs ¦ path ¦ …suivi de sa **valeur**.
-Filter ¦ param ¦ Filtre appliqué par le système de fichiers (rapide).
*.log ¦ val ¦ La valeur du filtre, avec joker.
-Recurse ¦ sw ¦ Un **commutateur** (switch) : pas de valeur, sa seule présence l’active.
```
>>> info ¦ Trois sortes de paramètres
```table
Sorte ¦ Exemple ¦ Particularité
Nommé ¦ `-Path C:\Logs` ¦ nom + valeur, dans n’importe quel ordre
Positionnel ¦ `Get-ChildItem C:\Logs` ¦ le nom est **sous-entendu** selon la position
Commutateur ¦ `-Recurse`, `-Force` ¦ vrai s’il est présent, faux sinon
```
`Get-ChildItem C:\Logs` fonctionne car `-Path` est le paramètre en **position 0**. `Get-Help Get-ChildItem -Parameter Path` l’indique (« Position ? 0 »).
>>> qcm ¦ Ces deux commandes sont-elles équivalentes ? `Get-Service -Name Spooler` et `Get-Service Spooler`
+ Oui, -Name est le paramètre positionnel de Get-Service
* Non, la seconde liste tous les services
* Non, la seconde provoque une erreur
* Oui, mais seulement en administrateur
? `-Name` est en position 0 pour Get-Service.
>>> info ¦ Abréger les noms de paramètres
On peut taper le **début** d’un nom de paramètre tant qu’il n’est pas ambigu : `-Rec` pour `-Recurse`, `-Fi` pour `-Filter`… mais `-F` est ambigu (Filter, Force, File).
!tip En console, abrège. Dans un script, écris le nom complet.
>>> type ps ¦ Liste récursivement tous les fichiers .log sous C:\Logs.
= Get-ChildItem -Path C:\Logs -Filter *.log -Recurse ;; Get-ChildItem C:\Logs -Filter *.log -Recurse ;; Get-ChildItem C:\Logs\*.log -Recurse ;; gci C:\Logs -Filter *.log -Recurse ;; dir C:\Logs -Filter *.log -Recurse ;; ls C:\Logs -Filter *.log -Recurse ;; Get-ChildItem C:\Logs -Recurse -Filter *.log ;; gci C:\Logs -Recurse -Filter *.log ;; Get-ChildItem -Path C:\Logs -Recurse -Filter *.log
>>> info ¦ Les paramètres communs
Toutes les cmdlets partagent des paramètres **communs** :
```table
Paramètre ¦ Rôle
`-WhatIf` ¦ **simule** : affiche ce qui serait fait, sans rien faire
`-Confirm` ¦ demande confirmation pour chaque élément
`-Verbose` ¦ affiche le détail des opérations
`-ErrorAction` ¦ que faire en cas d’erreur (`Stop`, `SilentlyContinue`, `Continue`…)
`-OutVariable` ¦ range aussi le résultat dans une variable
```
!it Avant un `Remove-Item` ou un `Disable-ADAccount` sur plusieurs éléments, ajoute **toujours** `-WhatIf` au premier passage.
>>> fill ps ¦ Vérifie ce que supprimerait la commande, sans rien supprimer.
```code ps
Remove-Item C:\Temp\*.tmp ___
```
= -WhatIf
~ -Force ;; -Recurse ;; /s ;; -Test
? `-WhatIf` affiche « WhatIf : Opération « Supprimer le fichier » en cours sur la cible … » pour chaque fichier, sans le supprimer.
>>> qcm ¦ Quelle est la valeur d’un commutateur comme `-Recurse` ?
+ Il n’en a pas : sa présence suffit
* Toujours `$true` à écrire après
* Un nombre de niveaux
* Un chemin
? On peut écrire `-Recurse:$false` pour le désactiver explicitement, mais c’est rare.

### LESSON p3 ¦ S’aider soi-même : Get-Help, Get-Command ¦ 1 ¦ Trouver la bonne commande et lire son aide, sans moteur de recherche.
>>> info ¦ Trois commandes pour tout découvrir
```table
Commande ¦ Question à laquelle elle répond
`Get-Command` ¦ « Quelle commande existe pour… ? »
`Get-Help` ¦ « Comment s’utilise cette commande ? »
`Get-Member` ¦ « Que contient ce résultat ? » (leçon suivante)
```
>>> info ¦ Get-Command avec des jokers
```code ps
Get-Command *firewall*
Get-Command -Verb Get -Noun *Disk*
Get-Command -Module ActiveDirectory
```
- `-Verb` / `-Noun` filtrent sur les deux moitiés du nom.
- `-Module` liste les commandes d’un module.
!tip Tu cherches comment gérer les imprimantes ? `Get-Command *print*` te donne `Get-Printer`, `Get-PrintJob`, `Remove-PrintJob`…
>>> type ps ¦ Trouve toutes les commandes dont le nom contient « print ».
= Get-Command *print* ;; Get-Command *Print* ;; gcm *print* ;; Get-Command -Name *print* ;; Get-Command -Noun *print*
>>> info ¦ Lire l’aide
```table
Commande ¦ Ce qu’elle montre
`Get-Help Get-Service` ¦ résumé et syntaxe
`Get-Help Get-Service -Examples` ¦ seulement les **exemples** (le plus utile !)
`Get-Help Get-Service -Full` ¦ tout, y compris chaque paramètre
`Get-Help Get-Service -Online` ¦ la page web Microsoft à jour
`Get-Help about_*` ¦ les articles de fond (`about_Operators`, `about_Quoting_Rules`…)
`Update-Help` ¦ télécharge l’aide complète (une fois, en administrateur)
```
>>> type ps ¦ Affiche uniquement les exemples de l’aide de Get-Process.
= Get-Help Get-Process -Examples ;; help Get-Process -Examples ;; Get-Help -Name Get-Process -Examples ;; man Get-Process -Examples ;; Get-Process -?
? `-?` derrière une cmdlet affiche aussi un résumé de son aide.
>>> info ¦ Lire une syntaxe
```code ps
Get-Service [[-Name] <string[]>] [-ComputerName <string[]>] [-DependentServices] [-Exclude <string[]>]
```
```table
Notation ¦ Signification
`[ … ]` autour du tout ¦ paramètre **facultatif**
`[-Name]` ¦ le **nom** du paramètre est facultatif : il est positionnel
`<string>` ¦ type de la valeur attendue : du texte
`<string[]>` ¦ les `[]` : plusieurs valeurs possibles, séparées par des virgules
pas de `<…>` ¦ commutateur
```
>>> qcm ¦ Dans la syntaxe, que signifie `<string[]>` après `-Name` ?
+ On peut passer un ou plusieurs textes, séparés par des virgules
* Le paramètre est obligatoire
* Le texte doit être entre crochets
* Le paramètre n’accepte pas de joker
? Exemple : `Get-Service -Name Spooler, wuauserv, BITS`.
>>> type ps ¦ Affiche l’état des services Spooler et wuauserv en une seule commande.
= Get-Service Spooler, wuauserv ;; Get-Service -Name Spooler, wuauserv ;; Get-Service Spooler,wuauserv ;; Get-Service -Name Spooler,wuauserv ;; Get-Service wuauserv, Spooler ;; Get-Service -Name wuauserv, Spooler ;; gsv Spooler, wuauserv

### LESSON p4 ¦ Tout est objet : Get-Member ¦ 2 ¦ La différence fondamentale avec CMD : des objets avec des propriétés et des méthodes.
>>> info ¦ Texte contre objets
En CMD, `tasklist` produit du **texte** : pour extraire une colonne, il faut découper des lignes.

En PowerShell, `Get-Process` produit des **objets** : chaque processus est une fiche avec des **propriétés** nommées (`Name`, `Id`, `CPU`, `WorkingSet`…). Le tableau affiché n’est qu’une **vue** de ces fiches.
```table
Notion ¦ Analogie ¦ Exemple
Objet ¦ une fiche ¦ le processus Outlook
Propriété ¦ un champ de la fiche ¦ `Id` = 7344
Méthode ¦ une action que la fiche sait faire ¦ `Kill()`
Type ¦ le modèle de fiche ¦ `System.Diagnostics.Process`
```
>>> info ¦ Get-Member : l’inventaire d’un objet
```code ps
Get-Service Spooler | Get-Member
```
```out

   TypeName : System.ServiceProcess.ServiceController

Name                MemberType Definition
----                ---------- ----------
Stop                Method     void Stop()
Start               Method     void Start(), void Start(string[] args)
DisplayName         Property   string DisplayName {get;}
Status              Property   System.ServiceProcess.ServiceControllerStatus Status {get;}
StartType           Property   System.ServiceProcess.ServiceStartMode StartType {get;}
```
- **TypeName** : le type d’objet.
- **Property** : une donnée lisible (`{get;}`) et parfois modifiable (`{get;set;}`).
- **Method** : une action, appelée avec des parenthèses.
>>> type ps ¦ Affiche seulement les propriétés des objets renvoyés par Get-Process.
= Get-Process | Get-Member -MemberType Property ;; Get-Process | gm -MemberType Property ;; gps | gm -MemberType Property ;; Get-Process | Get-Member -MemberType Properties ;; Get-Process | gm -MemberType Properties ;; Get-Process | Get-Member -Type Property
>>> info ¦ Lire une propriété avec le point
Entre parenthèses, une commande devient un objet dont on peut lire une propriété avec un **point** :
```code ps
(Get-Service Spooler).Status
(Get-Date).DayOfWeek
(Get-ChildItem C:\Logs).Count
```
```out
Running
Thursday
4
```
>>> fill ps ¦ Affiche seulement le nom d’affichage du service wuauserv.
```code ps
(Get-Service wuauserv)___
```
= .DisplayName
~ -DisplayName ;; [DisplayName] ;; .Name
? Les parenthèses exécutent d’abord la commande, le point accède à la propriété.
>>> info ¦ Ce que l’écran ne montre pas
Le tableau par défaut ne montre que **quelques** propriétés choisies par Microsoft. Pour tout voir :
```code ps
Get-Service Spooler | Select-Object *
Get-Service Spooler | Format-List *
```
!it Un collègue dit « Get-Service n’affiche pas le type de démarrage ». Si : la propriété `StartType` existe, elle n’est juste pas dans la vue par défaut. `Get-Service | Select-Object Name, Status, StartType`.
>>> qcm ¦ Pourquoi peut-on trier les processus par mémoire sans découper de texte ?
+ Parce que chaque processus est un objet avec une propriété numérique WorkingSet
* Parce que PowerShell lit la colonne WS(K) à l’écran
* Parce que Sort-Object devine les colonnes
* On ne peut pas
? Sort-Object travaille sur la vraie propriété (un nombre), pas sur le texte affiché.

### LESSON p5 ¦ Le pipeline et $_ ¦ 2 ¦ Passer des objets d’une commande à l’autre, et désigner « l’objet en cours ».
>>> info ¦ Le pipe transporte des objets
Comme en CMD, `|` relie deux commandes. Mais ici, ce sont des **objets entiers** qui passent, un par un :
```code ps
Get-Service wuauserv | Stop-Service
```
Stop-Service reçoit l’**objet service** et sait quoi en faire : pas besoin de recopier le nom.
```code ps
Get-Process | Sort-Object WorkingSet -Descending | Select-Object -First 5 Name, Id
```
```anatomy ps
Get-Process ¦ cmd ¦ Produit un objet par processus.
| ¦ op ¦ Passe chaque objet à la commande suivante.
Sort-Object WorkingSet -Descending ¦ cmd ¦ Trie selon la mémoire utilisée, du plus grand au plus petit.
| ¦ op ¦ Passe les objets triés.
Select-Object -First 5 Name, Id ¦ cmd ¦ Garde les 5 premiers, et seulement deux propriétés.
```
>>> order ps ¦ Construis : les 3 processus qui consomment le plus de processeur.
~ Get-Process ;; | ;; Sort-Object CPU -Descending ;; | ;; Select-Object -First 3
x~ Where-Object ;; Format-Table
? Ordre logique : produire → trier → couper. Couper avant de trier donnerait 3 processus au hasard.
>>> info ¦ $_ : l’objet en cours
Dans un bloc `{ }` du pipeline, **`$_`** désigne l’objet qui est en train de passer (on peut aussi écrire `$PSItem`).
```code ps
Get-Service | Where-Object { $_.Status -eq 'Stopped' }
```
```anatomy ps
Where-Object ¦ cmd ¦ Filtre : ne laisse passer que les objets pour lesquels le bloc est vrai.
{ … } ¦ sb ¦ Un **bloc de script** : du code exécuté pour chaque objet.
$_ ¦ var ¦ L’objet en cours (ici : un service).
.Status ¦ param ¦ Sa propriété Status.
-eq ¦ op ¦ **eq**ual : opérateur d’égalité.
'Stopped' ¦ str ¦ La valeur comparée.
```
>>> fill ps ¦ Garde uniquement les fichiers de plus de 1 000 octets.
```code ps
Get-ChildItem C:\Logs | Where-Object { ___.Length -gt 1000 }
```
= $_
~ $ ;; $this ;; %_ ;; @_
? `$_` = l’élément en cours. `-gt` = **g**reater **t**han.
>>> info ¦ Pourquoi pas = ou > ?
En PowerShell, `=` **affecte** une valeur et `>` **redirige** vers un fichier (comme en CMD). Les comparaisons utilisent donc des opérateurs à tiret :
```table
Opérateur ¦ Signification ¦ Mnémonique
`-eq` / `-ne` ¦ égal / différent ¦ **eq**ual / **n**ot **e**qual
`-gt` / `-ge` ¦ supérieur / supérieur ou égal ¦ **g**reater **t**han / **g**reater or **e**qual
`-lt` / `-le` ¦ inférieur / inférieur ou égal ¦ **l**ess **t**han / **l**ess or **e**qual
`-like` ¦ correspond au joker ¦ `'PC-RH-01' -like 'PC-RH*'`
`-match` ¦ correspond à l’expression régulière ¦ `'PC-RH-01' -match '^PC-\w+-\d+$'`
`-contains` ¦ la liste contient ¦ `@('a','b') -contains 'a'`
`-in` ¦ est dans la liste ¦ `'a' -in @('a','b')`
```
Toutes ignorent la casse ; les versions `-ceq`, `-clike`… (**c**ase-sensitive) la respectent.
>>> qcm ¦ Que fait `Get-Service | Where-Object { $_.Status = 'Running' }` ?
+ C’est une erreur de logique : `=` affecte au lieu de comparer
* Elle liste les services démarrés
* Elle démarre tous les services
* Elle liste les services arrêtés
? Il faut `-eq`. Avec `=`, PowerShell tente une affectation (et échoue ici, Status étant en lecture seule).
>>> type ps ¦ Liste les services arrêtés dont le type de démarrage est automatique (ceux qui auraient dû démarrer).
= Get-Service | Where-Object { $_.Status -eq 'Stopped' -and $_.StartType -eq 'Automatic' } ;; Get-Service | Where-Object { $_.StartType -eq 'Automatic' -and $_.Status -eq 'Stopped' } ;; Get-Service | ? { $_.Status -eq 'Stopped' -and $_.StartType -eq 'Automatic' } ;; gsv | ? { $_.Status -eq 'Stopped' -and $_.StartType -eq 'Automatic' } ;; Get-Service | where { $_.Status -eq 'Stopped' -and $_.StartType -eq 'Automatic' }
hint: Deux conditions reliées par `-and` dans le même bloc `{ }`.
? `-and` (et), `-or` (ou), `-not` ou `!` (non). Un service automatique arrêté est souvent le symptôme d’une panne.

### LESSON p6 ¦ Filtrer : Where-Object et -Filter ¦ 2 ¦ Les deux syntaxes de Where-Object, et pourquoi filtrer « à gauche ».
>>> info ¦ Deux écritures de Where-Object
```table
Syntaxe ¦ Exemple ¦ Quand l’utiliser
Bloc de script ¦ `Where-Object { $_.CPU -gt 100 }` ¦ toujours possible, conditions multiples
Simplifiée ¦ `Where-Object CPU -gt 100` ¦ une seule condition, plus lisible
```
Les deux font la même chose. La forme simplifiée existe depuis PowerShell 3.
>>> type ps ¦ Avec la syntaxe simplifiée, liste les processus dont le nom commence par « ms ».
= Get-Process | Where-Object Name -like 'ms*' ;; Get-Process | Where-Object Name -like "ms*" ;; Get-Process | where Name -like ms* ;; Get-Process | Where-Object Name -like ms* ;; gps | ? Name -like 'ms*' ;; Get-Process | ? Name -like 'ms*' ;; Get-Process | where Name -like 'ms*'
>>> info ¦ Filtrer à gauche
**Règle d’or** : filtre le plus tôt possible, idéalement **dans** la première commande, avec ses propres paramètres.
```code ps
# Lent : récupère TOUS les fichiers du disque, puis trie
Get-ChildItem C:\ -Recurse | Where-Object Extension -eq '.pst'

# Rapide : le système de fichiers ne renvoie que les .pst
Get-ChildItem C:\ -Recurse -Filter *.pst
```
!it Avec Active Directory, c’est encore plus vrai : `Get-ADUser -Filter *  | Where-Object …` rapatrie tout l’annuaire par le réseau, alors que `Get-ADUser -Filter "Department -eq 'RH'"` demande au contrôleur de faire le tri.
>>> qcm ¦ Pourquoi `Get-ChildItem -Filter *.pst` est-il plus rapide que `Get-ChildItem | Where-Object Extension -eq '.pst'` ?
+ Le filtrage est fait à la source : seuls les .pst sont transformés en objets
* Where-Object ne fonctionne pas sur les fichiers
* -Filter utilise plusieurs processeurs
* Ils ont la même vitesse
? Le paramètre `-Filter` est transmis au fournisseur (système de fichiers, AD…) qui ne renvoie que les correspondances.
>>> info ¦ -like et -match
- `-like` utilise des **jokers** : `*` (n’importe quoi), `?` (un caractère), `[a-c]` (plage).
- `-match` utilise une **expression régulière** (regex), bien plus puissante.
```code ps
Get-ADComputer -Filter * | Where-Object Name -match '^PC-(COMPTA|RH)-\d{2}$'
```
```table
Regex ¦ Signification
`^` / `$` ¦ début / fin du texte
`\d` ¦ un chiffre (**d**igit) ; `\d{2}` = deux chiffres
`\w` ¦ une lettre, un chiffre ou _ (**w**ord)
`(A|B)` ¦ A **ou** B
`.` ¦ n’importe quel caractère (`\.` pour un vrai point)
```
>>> fill ps ¦ Garde les postes dont le nom commence par « LAP- » (ordinateurs portables).
```code ps
Get-ADComputer -Filter * | Where-Object Name ___ 'LAP-*'
```
= -like
~ -match ;; -eq ;; -contains ;; =
? Avec un joker `*`, c’est `-like`. Avec `-match`, il faudrait `'^LAP-'`.
>>> qcm ¦ Que renvoie `'SRV-AD01' -match 'AD'` ?
+ `True` : le texte contient « AD » quelque part
* `False` : il faut que tout le texte corresponde
* Une erreur
* `AD`
? `-match` cherche **n’importe où** dans le texte, sauf si tu ancres avec `^` et `$`.

### LESSON p7 ¦ Choisir et trier : Select-Object et Sort-Object ¦ 2 ¦ Garder les bonnes colonnes, créer des colonnes calculées, trier sur plusieurs critères.
>>> info ¦ Select-Object : les colonnes et le nombre
```table
Usage ¦ Exemple
choisir des propriétés ¦ `Select-Object Name, Status, StartType`
les N premiers / derniers ¦ `Select-Object -First 5` / `-Last 5`
sans doublons ¦ `Select-Object -Unique`
**extraire** une valeur seule ¦ `Select-Object -ExpandProperty Name`
toutes les propriétés ¦ `Select-Object *`
```
>>> qcm ¦ Quelle différence entre `Select-Object Name` et `Select-Object -ExpandProperty Name` ?
+ Le premier renvoie des objets avec une propriété Name ; le second renvoie directement les textes
* Aucune
* Le second trie par nom
* Le premier ne fonctionne qu’avec Get-Service
? `-ExpandProperty` « déballe » la valeur. Indispensable pour passer une simple liste de noms à une autre commande ou l’écrire dans un fichier texte.
>>> info ¦ Les propriétés calculées
On peut **créer** une colonne avec une table de hachage `@{ Name = '…'; Expression = { … } }` :
```code ps
Get-ChildItem C:\Logs | Select-Object Name, @{Name='Taille (Ko)'; Expression={ [math]::Round($_.Length / 1KB, 1) }}
```
```anatomy ps
@{ … } ¦ sb ¦ Une **table de hachage** décrivant la nouvelle colonne.
Name='Taille (Ko)' ¦ param ¦ Le titre de la colonne (abrégeable en `N` ou `Label`/`L`).
Expression={ … } ¦ param ¦ Le calcul, refait pour chaque objet (abrégeable en `E`).
[math]::Round( … , 1) ¦ cmd ¦ Arrondi à 1 décimale, avec la classe .NET Math.
$_.Length / 1KB ¦ op ¦ Taille en octets divisée par 1 024. PowerShell comprend `KB`, `MB`, `GB`, `TB`.
```
```out

Name                  Taille (Ko)
----                  -----------
app.log                       0,4
backup_2026-10-06.log         0,9
backup_2026-10-07.log         1,2
install.log                   0,1
```
>>> fill ps ¦ Affiche les processus avec leur mémoire en Mo.
```code ps
Get-Process | Select-Object Name, @{N='Mo'; E={ $_.WorkingSet / ___ }}
```
= 1MB

>>> info ¦ CIM et WMI

>>> info ¦ Interroger un autre poste sans WinRM
Par défaut, `Get-CimInstance -ComputerName` utilise **WinRM** (protocole WS-Man). Sur un parc où WinRM n’est pas activé, on crée une **session CIM en DCOM**, l’ancien protocole RPC de WMI :
```code ps
$opt = New-CimSessionOption -Protocol Dcom
$s = New-CimSession -ComputerName PC-COMPTA-02 -SessionOption $opt
Get-CimInstance Win32_BIOS -CimSession $s
Get-CimInstance Win32_ComputerSystem -CimSession $s | Select-Object Model, UserName
Remove-CimSession $s
```
```anatomy ps
New-CimSessionOption ¦ cmd ¦ Prépare les options de connexion.
-Protocol Dcom ¦ param ¦ Force **DCOM** (RPC, port 135 + ports dynamiques) au lieu de WS-Man/WinRM (5985).
New-CimSession ¦ cmd ¦ Ouvre une connexion réutilisable vers le poste.
-CimSession $s ¦ param ¦ Les requêtes suivantes passent par cette session.
Remove-CimSession ¦ cmd ¦ Ferme proprement la connexion.
```
!tip `Get-WmiObject -ComputerName PC` (5.1) utilise aussi DCOM directement. Le script d’équipe `C:\Scripts\inventaire.ps1` utilise la méthode CimSession + DCOM : tu l’étudieras dans une mission.
>>> qcm ¦ `Get-CimInstance Win32_BIOS -ComputerName PC-COMPTA-02` échoue avec une erreur WinRM. Que faire sur un parc sans WinRM ?
+ Créer une CimSession avec `New-CimSessionOption -Protocol Dcom`
* Lancer `winrm quickconfig` sur le poste
* Utiliser Enter-PSSession
* Ce n’est pas possible
? DCOM passe par RPC, comme les outils de gestion classiques. Le pare-feu du poste doit autoriser « Infrastructure de gestion Windows (WMI) ».
>>> qcm ¦ Pourquoi éviter `Get-CimInstance Win32_Product` pour lister les logiciels installés ?
+ Elle est très lente et déclenche une vérification de réparation de chaque programme MSI
* Elle n’existe pas
* Elle exige WinRM
* Elle ne liste que les logiciels Microsoft
? Win32_Product fait vérifier chaque MSI par Windows Installer (journal 1035 dans l’Observateur), parfois avec des réparations. Préfère le Registre (`…\Uninstall`), vu dans la leçon sur le registre.
