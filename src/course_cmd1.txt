=== cmd ¦ Invite de commandes (CMD) ¦ cmd ¦ Fichiers, réseau, services, domaine et scripts .bat : les commandes tapées chaque jour au support.
--- Naviguer et gérer les fichiers
### LESSON c1 ¦ Se déplacer : cd, dir, cls ¦ 1 ¦ Savoir où l’on est, changer de dossier, de lecteur, et lire une liste.
>>> info ¦ Où suis-je ?
L’invite t’indique toujours le **dossier courant** : `C:\Users\it.tech>`. Trois commandes suffisent pour circuler :

- `cd` (**C**hange **D**irectory) : sans argument, affiche le dossier courant ; avec un chemin, s’y déplace.
- `dir` (**DIR**ectory) : liste le contenu d’un dossier.
- `cls` (**CL**ear **S**creen) : efface l’écran.
```code cmd
cd C:\Logs
dir
```
>>> info ¦ Le piège du changement de lecteur
CMD mémorise **un dossier courant par lecteur**. Depuis C:, `cd D:\Backup` change le dossier courant de D:… mais l’invite reste sur C: !
```code cmd
cd D:\Backup
cd
```
```out
C:\Users\it.tech
```
Deux solutions : taper la lettre seule (`D:`), ou ajouter `/d`.
```anatomy cmd
cd ¦ cmd ¦ **C**hange **D**irectory : changer de dossier courant.
/d ¦ sw ¦ **D**rive : change aussi de lecteur en même temps.
D:\Backup ¦ path ¦ Le dossier de destination, sur un autre lecteur.
```
>>> qcm ¦ Tu es sur C: et tu tapes `cd D:\Backup`. Que se passe-t-il ?
+ L’invite reste sur C: ; seul le dossier courant de D: change
* L’invite passe sur D:\Backup
* CMD affiche une erreur
* CMD crée le dossier D:\Backup
? Sans `/d`, CMD change le dossier « mémorisé » de D: sans changer de lecteur. Tape `D:` ou `cd /d D:\Backup`.
>>> type cmd ¦ Va dans D:\Backup en changeant aussi de lecteur.
= cd /d D:\Backup ;; cd D:\Backup /d ;; pushd D:\Backup ;; chdir /d D:\Backup
```out

D:\Backup>
```
? `cd /d` change de lecteur et de dossier d’un coup. `pushd` fait de même et mémorise l’ancien emplacement (retour avec `popd`).
>>> info ¦ Lire la sortie de dir
```out

 Le numéro de série du volume est 7A3C-91F2
```

- Date et heure de **dernière modification**.

>>> qcm ¦ Dans la sortie de `dir`, que signifie `<DIR>` ?
+ L’entrée est un dossier
* Le fichier est caché
* Le fichier est en lecture seule
* Le dossier est vide
? `<DIR>` remplace la taille pour les dossiers. Les fichiers cachés n’apparaissent pas du tout sans `/a`.
>>> type cmd ¦ Efface l’écran de la console.
= cls
? `cls` vide l’affichage, pas l’historique : la flèche haut retrouve toujours tes commandes.

### LESSON c2 ¦ dir en profondeur : /a /s /b /o /w ¦ 1 ¦ Fichiers cachés, recherche récursive, tri par taille.
>>> info ¦ Une commande, beaucoup d’options
```anatomy cmd
dir ¦ cmd ¦ Liste le contenu d’un dossier.
C:\Users ¦ path ¦ Le dossier de départ.
/a:h ¦ sw ¦ **A**ttributes : seulement les éléments ayant l’attribut **h** (**h**idden, caché).
/s ¦ sw ¦ **S**ubdirectories : descend dans tous les sous-dossiers.
/b ¦ sw ¦ **B**are : affichage brut, un chemin complet par ligne (idéal pour un fichier ou un pipe).
```
>>> info ¦ Les lettres de /a et de /o
```table
/a: ¦ Signification ¦ /o: ¦ Signification
`h` ¦ caché (hidden) ¦ `n` ¦ par nom
`s` ¦ système ¦ `s` ¦ par taille (size)
`d` ¦ dossier (directory) ¦ `d` ¦ par date
`r` ¦ lecture seule (read-only) ¦ `e` ¦ par extension
`a` ¦ prêt à archiver ¦ `g` ¦ dossiers en premier (group)
`-` ¦ inverse : `/a:-d` = pas les dossiers ¦ `-` ¦ ordre inverse : `/o:-s` = plus gros d’abord
```
`/a` seul affiche **tout**, cachés et système compris.
>>> type cmd ¦ Liste C:\Data\Compta du plus gros fichier au plus petit.
= dir C:\Data\Compta /o:-s ;; dir C:\Data\Compta /o-s ;; dir /o:-s C:\Data\Compta ;; dir /o-s C:\Data\Compta
hint: `/o` pour l’ordre, `s` pour la taille, et un `-` pour inverser.
```out
 Répertoire de C:\Data\Compta

06/10/2026  09:15    <DIR>          .
06/10/2026  09:15    <DIR>          ..
30/09/2026  11:32         1 843 211 factures_septembre.pdf
26/09/2026  17:04           248 320 bilan_2025.xlsx
06/10/2026  09:15            56 320 notes_de_frais.xlsx
13/03/2026  09:00    <DIR>          Archives
               3 fichier(s)        2 147 851 octets
               3 Rép(s)  41 234 567 168 octets libres
```
>>> fill cmd ¦ Affiche les fichiers cachés du profil.
```code cmd
dir C:\Users\it.tech ___
```
= /a:h
~ /h ;; /a:d ;; /s ;; /q
? `/a:h` filtre sur l’attribut caché. Tu verras par exemple `AppData` et `NTUSER.DAT`. Il n’existe pas de `/h` pour dir.
>>> qcm ¦ Que liste `dir /a:-d` ?
+ Uniquement les fichiers, sans les dossiers
* Uniquement les dossiers
* Les fichiers supprimés
* Les dossiers cachés
? Le `-` inverse l’attribut : « tout sauf les dossiers ». Et comme `/a` est présent, les fichiers cachés sont inclus.
>>> type cmd ¦ Cherche sous C:\Users tous les fichiers .pst (archives Outlook), en chemins complets.
= dir C:\Users\*.pst /s /b ;; dir /s /b C:\Users\*.pst ;; dir C:\Users\*.pst /b /s ;; dir /b /s C:\Users\*.pst
hint: Le motif `*.pst` derrière le dossier, puis `/s` (sous-dossiers) et `/b` (brut).
```out
C:\Users\jdupont\Documents\Fichiers Outlook\archives_2024.pst
C:\Users\smartin\Documents\Fichiers Outlook\Sophie_Martin.pst
```
!it Avant une migration de messagerie, on recense les fichiers .pst pour les importer dans les boîtes Exchange Online.
>>> qcm ¦ Quel commutateur affiche les noms sur plusieurs colonnes ?
+ `/w`
* `/c`
* `/l`
* `/p`
? `/w` = **w**ide. `/p` fait une **p**ause à chaque écran, `/l` affiche en minuscules (**l**owercase).

### LESSON c3 ¦ Créer, renommer, supprimer : md, ren, del, rd ¦ 1 ¦ Gérer fichiers et dossiers proprement, sans mauvaise surprise.
>>> info ¦ Créer des dossiers : md
`md` (**M**ake **D**irectory, alias `mkdir`) crée un dossier. Il crée aussi tous les dossiers intermédiaires manquants.
```code cmd
md C:\Temp\Audit\2026\Octobre
```
Si le dossier existe déjà : « Un sous-répertoire ou un fichier C:\Temp\Audit existe déjà. »
>>> type cmd ¦ Crée le dossier C:\Temp\Audit.
= md C:\Temp\Audit ;; mkdir C:\Temp\Audit ;; md "C:\Temp\Audit"
? `md` et `mkdir` sont identiques.
>>> info ¦ Renommer : ren
`ren` (**REN**ame) prend l’ancien nom puis le **nouveau nom seul**, sans chemin. Les jokers marchent pour changer les extensions.
```code cmd
ren C:\Temp\rapport.txt rapport_ancien.txt
ren C:\Temp\*.txt *.bak
```
!warn Pour déplacer un fichier vers un autre dossier, c’est `move`, pas `ren`.
>>> qcm ¦ Que répond CMD à `ren C:\Temp\a.txt D:\b.txt` ?
+ « La syntaxe de la commande n’est pas correcte. »
* Le fichier est déplacé vers D: et renommé
* Le fichier est copié
* Rien, la commande réussit
? Le second argument de `ren` doit être un nom, pas un chemin. Pour changer de dossier ou de lecteur, utilise `move`.
>>> info ¦ Supprimer des fichiers : del
```anatomy cmd
del ¦ cmd ¦ **DEL**ete : supprime des fichiers (jamais des dossiers). Alias : `erase`.
/s ¦ sw ¦ **S**ubdirectories : dans le dossier et tous ses sous-dossiers.
/q ¦ sw ¦ **Q**uiet : sans question « Êtes-vous sûr ? ».
/f ¦ sw ¦ **F**orce : supprime aussi les fichiers en lecture seule.
C:\Temp\*.tmp ¦ path ¦ Ce qu’il faut supprimer : tous les .tmp de C:\Temp.
```
!warn `del` ne passe pas par la Corbeille. Les fichiers cachés ou système sont ignorés, sauf avec `/a`.
>>> info ¦ Supprimer des dossiers : rd
`rd` (**R**emove **D**irectory, alias `rmdir`) ne supprime qu’un dossier **vide**. Pour un dossier plein : `/s` supprime l’arborescence et `/q` évite la confirmation.
```code cmd
rd C:\Temp\cache
rd /s /q C:\Temp\cache
```
```out
Le répertoire n’est pas vide.
```
>>> fill cmd ¦ Supprime le dossier C:\Temp\cache et tout son contenu, sans confirmation.
```code cmd
rd ___ ___ C:\Temp\cache
```
= /s ;; /q
~ /f ;; /a ;; /y
? `/s` pour l’arborescence, `/q` pour le silence. L’ordre des deux commutateurs est libre.
>>> qcm ¦ Pourquoi `rd C:\Temp\cache` répond « Le répertoire n’est pas vide » ?
+ Sans `/s`, rd ne supprime que les dossiers vides
* Un fichier du dossier est ouvert
* Il faut des droits administrateur
* Le dossier est caché
? C’est une sécurité. Ajoute `/s` (et `/q` pour ne pas être interrogé).
>>> type cmd ¦ Supprime tous les fichiers .tmp de C:\Temp, sans confirmation.
= del /q C:\Temp\*.tmp ;; del C:\Temp\*.tmp /q ;; erase /q C:\Temp\*.tmp ;; del /f /q C:\Temp\*.tmp ;; del /q /f C:\Temp\*.tmp ;; del C:\Temp\*.tmp ;; del "C:\Temp\*.tmp"
? Avec un motif précis comme `*.tmp`, CMD ne demande pas confirmation ; avec `*` ou `*.*`, il le fait, d’où `/q`.

### LESSON c4 ¦ Copier : copy, xcopy, robocopy ¦ 2 ¦ Trois générations d’outils, et pourquoi robocopy est roi.
>>> info ¦ Trois outils, trois époques
```table
Outil ¦ Usage ¦ À retenir
`copy` ¦ un ou plusieurs fichiers ¦ pas de sous-dossiers
`xcopy` ¦ arborescences ¦ ancien, toujours là, dépassé par robocopy
`robocopy` ¦ copies sérieuses ¦ reprise, miroir, tentatives, journal, multithread
```
```code cmd
copy C:\Data\nouveaux.csv D:\Backup\
```
```out
        1 fichier(s) copié(s).
```
>>> info ¦ Robocopy, ligne par ligne
**Robocopy** = **Ro**bust **Copy**. C’est l’outil de référence pour sauvegarder, migrer un serveur de fichiers ou un profil.
```anatomy cmd
robocopy ¦ cmd ¦ **Ro**bust file **copy**.
C:\Data\Compta ¦ path ¦ La **source** (un dossier, jamais un fichier).
\\SRV-FICHIERS\Backup\Compta ¦ path ¦ La **destination**, ici un partage réseau.
/MIR ¦ sw ¦ **MIR**ror : la destination devient identique à la source (= `/E` + `/PURGE`). Ce qui n’existe plus dans la source est **supprimé** de la destination.
/Z ¦ sw ¦ Mode redémarrable : reprend un gros fichier là où la copie s’est coupée.
/R:2 ¦ sw ¦ **R**etry : 2 nouvelles tentatives en cas d’échec (défaut : 1 million !).
/W:5 ¦ sw ¦ **W**ait : 5 secondes entre deux tentatives (défaut : 30).
/LOG:C:\Logs\copie.log ¦ sw ¦ Écrit le rapport dans un journal (`/LOG+:` ajoute au lieu d’écraser).
```
!warn `/MIR` dans le mauvais sens (destination vide vers source pleine) **efface la source**. Teste toujours d’abord avec `/L`.
>>> info ¦ Les options de robocopy à connaître
```table
Option ¦ Effet
`/E` ¦ sous-dossiers, y compris vides (**E**mpty)
`/S` ¦ sous-dossiers, sauf vides (**S**ubdirectories)
`/L` ¦ **L**iste seulement : montre ce qui serait copié, sans rien faire
`/MT:16` ¦ **M**ulti**T**hread : 16 copies en parallèle (défaut 8)
`/XO` ¦ e**X**clut les fichiers plus anciens (**O**lder) que ceux de la destination
`/XF *.tmp` ¦ e**X**clut des **F**ichiers
`/XD Cache` ¦ e**X**clut des **D**ossiers
`/COPY:DAT` ¦ copie **D**onnées, **A**ttributs, horodatage (**T**imestamps) ; `DATSOU` ajoute sécurité, propriétaire, audit
`/MOV` ¦ déplace (supprime la source après copie)
`/NP` ¦ pas de pourcentage (**N**o **P**rogress) : journaux lisibles
`/TEE` ¦ écrit à l’écran **et** dans le journal
```
>>> info ¦ Les codes de sortie de robocopy
Robocopy renvoie un code dans `%ERRORLEVEL%`. Contrairement aux autres outils, **1 n’est pas une erreur**.
```table
Code ¦ Signification
`0` ¦ rien à copier, tout était à jour
`1` ¦ des fichiers ont été copiés
`2` ¦ des fichiers en trop dans la destination (extras)
`3` ¦ 1 + 2
`4` ¦ des différences ont été détectées
`8` et plus ¦ au moins une copie a **échoué**
```
Dans un script : `if %ERRORLEVEL% GEQ 8 echo ECHEC`.
>>> qcm ¦ Une sauvegarde robocopy se termine avec le code 1. Que conclure ?
+ Des fichiers ont été copiés, sans erreur
* La sauvegarde a échoué
* Rien n’a été copié
* Un fichier était verrouillé
? Pour robocopy, les codes 0 à 7 sont des succès. L’échec commence à 8.
>>> qcm ¦ Quelle option permet de tester une commande robocopy sans rien copier ni supprimer ?
+ `/L`
* `/T`
* `/TEST`
* `/Z`
? `/L` (**L**ist only) affiche tout ce qui serait fait. Indispensable avant un premier `/MIR`.
>>> type cmd ¦ Copie C:\Data\RH vers D:\Backup\RH, sous-dossiers vides compris, avec 2 tentatives espacées de 5 secondes.
=~ ^robocopy "?C:\\Data\\RH\\?"? "?D:\\Backup\\RH\\?"?( /(E|R:2|W:5)){3}$
sol: robocopy C:\Data\RH D:\Backup\RH /E /R:2 /W:5
hint: Source, destination, puis `/E`, `/R:2` et `/W:5` (dans l’ordre que tu veux).

>>> info ¦ xcopy, pour comprendre les vieux scripts
```table
Commutateur ¦ Mot ¦ Effet
`/E` ¦ **E**mpty ¦ sous-dossiers, même vides
`/S` ¦ **S**ubdirectories ¦ sous-dossiers non vides
`/I` ¦ d**I**rectory ¦ la destination est un dossier (évite la question F/R)
`/H` ¦ **H**idden ¦ inclut fichiers cachés et système
`/Y` ¦ **Y**es ¦ écrase sans demander
`/C` ¦ **C**ontinue ¦ continue malgré les erreurs
`/D` ¦ **D**ate ¦ ne copie que les fichiers plus récents
```
>>> fill cmd ¦ Dépose le dossier C:\Scripts sur le disque C: de PC-COMPTA-02, via le partage administratif.
```code cmd
xcopy C:\Scripts \\PC-COMPTA-02\C$\Scripts ___ ___
```
= /E ;; /I
~ /Q ;; /Z ;; /MIR
? `/E` copie toute l’arborescence, `/I` indique que la destination est un dossier. `/MIR` n’existe que dans robocopy.

### LESSON c5 ¦ Lire et chercher : type, more, find, findstr ¦ 1 ¦ Afficher un fichier et trouver une ligne dans des journaux.
>>> info ¦ Afficher un fichier texte
- `type fichier.txt` : affiche tout le contenu d’un coup.
- `more fichier.txt` : page par page (Espace pour continuer, Q pour quitter).
- `type nul > vide.txt` : crée un fichier vide.
```code cmd
type C:\Users\it.tech\Desktop\notes.txt
```
>>> info ¦ find et findstr : chercher du texte
```anatomy cmd
findstr ¦ cmd ¦ **FIND STR**ing : cherche un texte dans des fichiers ou dans un pipe.
/s ¦ sw ¦ **S**ubdirectories : dans les sous-dossiers aussi.
/i ¦ sw ¦ **I**gnore case : sans tenir compte des majuscules.
/m ¦ sw ¦ **M**atch files : affiche seulement le nom des fichiers qui contiennent le texte.
"erreur" ¦ str ¦ Le texte cherché.
C:\Logs\*.log ¦ path ¦ Où chercher.
```
>>> info ¦ find ou findstr ?
```table
 ¦ find ¦ findstr
Recherche ¦ un texte exact, toujours entre guillemets ¦ un ou plusieurs mots, ou une expression régulière
Plusieurs mots ¦ non ¦ `"a b"` = a **OU** b ; `/c:"a b"` = la phrase exacte
Compter ¦ `/c` (**c**ount) ¦ non
Numéroter ¦ `/n` ¦ `/n`
Inverser ¦ `/v` ¦ `/v`
Ignorer la casse ¦ `/i` ¦ `/i`
Sous-dossiers ¦ non ¦ `/s`
```
!warn `findstr "délai de réponse"` cherche « délai » OU « de » OU « réponse ». Pour la phrase exacte : `findstr /c:"délai de réponse"`.
>>> type cmd ¦ Affiche les lignes de C:\Logs\app.log qui contiennent « erreur », sans tenir compte de la casse.
= findstr /i erreur C:\Logs\app.log ;; findstr /i "erreur" C:\Logs\app.log ;; find /i "erreur" C:\Logs\app.log ;; findstr /i "ERREUR" C:\Logs\app.log ;; findstr /i ERREUR C:\Logs\app.log ;; find /i "ERREUR" C:\Logs\app.log ;; findstr "ERREUR" C:\Logs\app.log ;; find "ERREUR" C:\Logs\app.log
```out
2026-10-08 08:40:11 ERREUR Connexion SQL refusée : SRV-APP01 injoignable
2026-10-08 08:40:41 ERREUR Connexion SQL refusée : SRV-APP01 injoignable
```
? `findstr` et `find` conviennent ici. Avec `find`, le texte doit toujours être entre guillemets.
>>> type cmd ¦ Compte combien de lignes de C:\Logs\app.log contiennent « ERREUR ».
= find /c "ERREUR" C:\Logs\app.log ;; find /c /i "erreur" C:\Logs\app.log ;; find /i /c "erreur" C:\Logs\app.log ;; find /c /i "ERREUR" C:\Logs\app.log ;; find /i /c "ERREUR" C:\Logs\app.log ;; find "ERREUR" /c C:\Logs\app.log

```out

---------- C:\LOGS\APP.LOG: 2
```
>>> qcm ¦ Que fait `findstr "ERREUR WARN" C:\Logs\app.log` ?
+ Affiche les lignes qui contiennent ERREUR ou WARN
* Affiche les lignes qui contiennent la phrase « ERREUR WARN »
* Affiche les lignes qui contiennent les deux mots
* Renvoie une erreur de syntaxe
? Les mots séparés par un espace sont des alternatives. Pratique pour filtrer plusieurs niveaux de gravité d’un coup.
>>> fill cmd ¦ Cherche la phrase exacte « délai de réponse » dans app.log.
```code cmd

```
= /c
~ /r ;; /s ;; /x ;; /m
? `/c:` traite tout le texte comme une seule chaîne littérale, espaces compris.

### LESSON c6 ¦ Redirections et pipes : > >> | && || ¦ 2 ¦ Envoyer une sortie dans un fichier, chaîner des commandes, réagir à un échec.
>>> info ¦ Les symboles d’enchaînement
```table
Symbole ¦ Effet ¦ Exemple
`>` ¦ envoie la sortie dans un fichier (l’écrase) ¦ `ipconfig /all > diag.txt`
`>>` ¦ ajoute à la fin du fichier ¦ `echo %DATE% >> journal.txt`
`2>` ¦ envoie les **erreurs** dans un fichier ¦ `dir X: 2> erreurs.txt`
`2>&1` ¦ envoie les erreurs au même endroit que la sortie ¦ `… > log.txt 2>&1`
`> nul` ¦ jette la sortie ¦ `ping srv-ad01 > nul`
`<` ¦ lit l’entrée depuis un fichier ¦ `sort < liste.txt`
`|` ¦ pipe : la sortie de gauche devient l’entrée de droite ¦ `ipconfig | findstr IPv4`
`&` ¦ enchaîne, quoi qu’il arrive ¦ `cls & dir`
`&&` ¦ lance la suivante **si** la première réussit ¦ `md X && cd X`
`||` ¦ lance la suivante **si** la première échoue ¦ `ping -n 1 X > nul || echo KO`
```
>>> info ¦ Un diagnostic dans un fichier
```anatomy cmd
ipconfig ¦ cmd ¦ La commande dont on veut garder le résultat.
/all ¦ sw ¦ Configuration complète.
> ¦ op ¦ **Redirection** : la sortie part dans un fichier au lieu de l’écran (le fichier est écrasé).
C:\Temp\diag.txt ¦ path ¦ Le fichier de destination.
2>&1 ¦ op ¦ Les messages d’erreur (flux 2) vont au même endroit que la sortie normale (flux 1).
```
!it Pour un utilisateur à distance, fais-lui lancer la commande avec redirection, puis récupère le fichier par `\\PC\C$\Temp\diag.txt`.
>>> qcm ¦ Quelle différence entre `>` et `>>` ?
+ `>` écrase le fichier, `>>` ajoute à la fin
* `>` ajoute, `>>` écrase
* `>>` redirige les erreurs
* Aucune différence
? Pour un journal qui grossit à chaque exécution, c’est `>>`. Pour un rapport neuf à chaque fois, `>`.
>>> type cmd ¦ Enregistre la sortie de ipconfig /all dans C:\Temp\diag.txt.
= ipconfig /all > C:\Temp\diag.txt ;; ipconfig /all >C:\Temp\diag.txt ;; ipconfig /all > "C:\Temp\diag.txt" ;; ipconfig /all 1> C:\Temp\diag.txt
? Rien ne s’affiche : tout est parti dans le fichier. Vérifie avec `type C:\Temp\diag.txt`.
>>> info ¦ Le pipe dans CMD : du texte qui passe
Le `|` envoie les **lignes** affichées par la commande de gauche vers celle de droite. Dans CMD, la droite est souvent un filtre : `find`, `findstr`, `sort`, `more`.
```code cmd
ipconfig | findstr IPv4
tasklist | findstr /i outlook
```
```out
   Adresse IPv4. . . . . . . . . . . . . .: 192.168.10.42
OUTLOOK.EXE                   7344 Console                    1   348 168 Ko
```
>>> order cmd ¦ Construis la commande qui affiche seulement la ligne d’Outlook dans la liste des processus.
~ tasklist ;; | ;; findstr ;; /i ;; outlook
x~ > ;; &&

* Rend le fichier exécutable
* Lance le script en administrateur

- `ping 8.8.8.8` : **Internet** répond par adresse IP.
- `ping google.com` : la **résolution DNS** fonctionne.
Le premier cercle qui échoue désigne la panne.

* Dans la passerelle
* Le site google.com est en panne

>>> info ¦ Passer en IP fixe, puis revenir en DHCP

>>> info ¦ Réinitialiser la pile réseau
Après une désinstallation de VPN ou d’antivirus, la pile réseau peut rester abîmée : pages qui ne chargent pas, erreurs de socket. Deux commandes la remettent à neuf :
```code cmd
netsh winsock reset
netsh int ip reset
```
```out

Catalogue Winsock réinitialisé.
Vous devez redémarrer l’ordinateur pour terminer la réinitialisation.
```
